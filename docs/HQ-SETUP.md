# HQ («Штаб») — ассистент группы компаний

Телеграм-бот, который ведёт задачи двух основателей по **всем компаниям
группы**: постановка, лестница напоминаний, эскалация при просрочке,
приёмка работы постановщиком и две сводки в день.

Система стоит **над** бизнесами, а не внутри одного из них: LEGAR здесь —
одна из компаний холдинга, наравне с остальными. Название системы («Штаб»)
меняется в `hq_settings.brand` без деплоя.

Запуск — 20 минут, из них 15 занимает BotFather.

---

## 1. Создать бота

1. В Telegram открыть **@BotFather** → `/newbot`.
2. Имя — любое (например «Штаб»), username — свободный, например `hq_ms_bot`.
   Имя лучше нейтральное: бот ведёт всю группу компаний, а не один бизнес.
3. BotFather пришлёт **токен** — это `TELEGRAM_HQ_BOT_TOKEN`.
4. Там же: `/setprivacy` → выбрать бота → **Disable**.
   Без этого бот не увидит сообщения в общем чате.

## 2. Прогнать миграцию

В Supabase Dashboard → SQL Editor выполнить по очереди
`supabase/migrations/004_hq_assistant.sql`, затем `005_hq_holding.sql`.

## 3. Переменные окружения (Vercel → Settings → Environment Variables)

| Переменная | Что это |
|---|---|
| `TELEGRAM_HQ_BOT_TOKEN` | токен из BotFather |
| `TELEGRAM_HQ_WEBHOOK_SECRET` | любая случайная строка — Telegram будет присылать её в заголовке |
| `HQ_BOOTSTRAP_CODE` | одноразовый код, по которому вы регистрируетесь в боте |
| `HQ_CRON_SECRET` | ключ, которым Supabase дёргает `/api/hq/tick` |

Уже должны быть в проекте: `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`.

После добавления — задеплоить (`git push` в `main`).

## 4. Привязать вебхук

```bash
TELEGRAM_HQ_BOT_TOKEN=... \
TELEGRAM_HQ_WEBHOOK_SECRET=... \
HQ_URL=https://legar.com.ua \
node scripts/hq-set-webhook.mjs
```

Проверить состояние потом — тот же скрипт без `HQ_URL`.

## 5. Зарегистрироваться

Каждый пишет боту в личку:

```
/start ВАШ_HQ_BOOTSTRAP_CODE
```

Первый, кто это сделает, получает права админа. После регистрации обоих
код можно убрать из переменных.

Дальше каждый задаёт формы своего имени, чтобы бот узнавал их в тексте:

```
/alias серёжа сергею сереже серж
```

## 6. Общий чат (необязательно, но удобно)

Создать группу «Штаб», добавить туда бота и сделать администратором.
В группе бот берёт в работу только сообщения, начинающиеся с `+`,
и команды — обсуждение задачами не становится.

```
+ Серёже КП по маркетингу до 20:00 #hotels
```

## 7. Сердцебиение — раз в минуту

Напоминания требуют проверки каждую минуту. Vercel на текущем тарифе умеет
крон только раз в сутки, поэтому используем `pg_cron` в Supabase.

SQL Editor → выполнить один раз (подставив свой домен и `HQ_CRON_SECRET`):

```sql
create extension if not exists pg_cron;
create extension if not exists pg_net;

select cron.schedule(
  'hq-tick',
  '* * * * *',
  $$
  select net.http_get(
    url := 'https://legar.com.ua/api/hq/tick?key=ВАШ_HQ_CRON_SECRET',
    timeout_milliseconds := 8000
  );
  $$
);
```

Проверить: `select * from cron.job;`
Снять: `select cron.unschedule('hq-tick');`

Ручная проверка из терминала:

```bash
curl "https://legar.com.ua/api/hq/tick?key=ВАШ_HQ_CRON_SECRET"
# {"ok":true,"fired":0,"queued":0,"digests":[]}
```

## 8. Структура группы компаний

Два уровня: **компания** → **направление внутри неё**.

```
/projects hotels Отели            ← компания
/projects legar LEGAR             ← компания
/projects hotels/smm SMM          ← направление внутри «Отелей»
/projects legar/sales Продажи
```

Дальше в тексте задачи достаточно `#hotels`, `#smm` — или просто упомянуть
название. Если совпали и компания, и направление, бот берёт направление как
более конкретное.

Посмотреть дерево — `/projects` без аргументов. Всё по одной компании —
`/co hotels`.

## Как это работает

### Постановка

Обычным текстом в личке боту (или с `+` в общем чате):

```
Серёже КП по маркетингу до 20:00 #hotels
мне позвонить в банк завтра в 11:00
Вике созвон по отелям в пятницу в 15:00
```

Бот разбирает исполнителя, срок, проект и тип (задача или событие) и
показывает карточку. Пока не нажали «Поставить» — задача не создана.

Понимает: `сегодня`, `завтра`, `послезавтра`, `до 20:00`, `к обеду`,
`утром`, `вечером`, `через 2 часа`, `в пятницу`, `12.08 в 15:00`,
`до конца дня`, `до конца недели`.

### Напоминания

| | Лестница |
|---|---|
| Задача | за сутки → за 3 часа → за час → в момент срока |
| Событие (звонок, встреча) | за сутки → за 2 часа → за час → за 10 минут |

Событие распознаётся по словам: звонок, созвон, встреча, планёрка, zoom,
интервью, переговоры, презентация.

Ночью (22:00–08:00) бот молчит и переносит напоминание на утро. Сам момент
дедлайна не сдвигается никогда.

### Эскалация

Срок прошёл, задача не закрыта → пинг исполнителю каждые 30 минут (до 8 раз),
постановщик узнаёт сразу и потом через раз. Работа сдана, но не принята
больше 2 часов → напоминание постановщику.

### Приёмка

«Готово» не закрывает задачу. Исполнитель прикладывает результат (текст,
ссылка или файл), постановщик получает карточку с кнопками **Принять** /
**Вернуть**. Закрывает только постановщик. Если задачу ставили себе —
закрывается сразу.

### Защита от перегруза

- Задача без срока не создаётся — бот спросит дедлайн.
- Больше 3 активных задач на человека — бот показывает текущую загрузку и
  просит подтвердить («Всё равно поставить»).
- Каждый перенос считается. С третьего бот пишет постановщику, что задача,
  скорее всего, поставлена не тому или не туда.

### Сводки

- **08:30** — что сегодня, что просрочено, что ждёт вашей приёмки, звонки по времени.
- **20:30** — что закрыто, что осталось, что завтра.
- `/stats` — за неделю: закрыто, % в срок, просрочено сейчас, сколько
  переносов, **и разрез по компаниям** — где именно всё скапливается.

Время сводок, тихие часы, шаг эскалации, лимит задач и название системы
меняются в таблице `hq_settings` без деплоя.

## Команды

| Команда | Что делает |
|---|---|
| `/my` | мои активные задачи |
| `/all` | все активные задачи обоих, с разбивкой по компаниям |
| `/today` | сегодня и просроченное |
| `/co <компания>` | всё по одной компании группы |
| `/task <текст>` | поставить задачу явно |
| `/t <id>` | открыть карточку задачи |
| `/projects` | структура группы; `/projects key Название` — компания, `/projects комп/напр Название` — направление |
| `/alias ...` | формы своего имени для распознавания |
| `/people` | кто в системе |
| `/stats` | сводка за неделю |
| `/me` | мой Telegram ID |
| `/help` | справка |

## Чего бот не делает

**Не читает вашу личную переписку в Telegram** — Bot API так не умеет.
Видит только то, что написали ему: в личку или в общий чат, где он админ.
Обход через userbot от вашего имени возможен технически, но нарушает правила
Telegram и рискует аккаунтом — сознательно не используем.

**Не наследует данные из других AI-чатов и агентов.** Контекст, который вы
давали другому ассистенту, живёт только в том чате. Всё, что должно быть у
бота под рукой, живёт в базе: люди (`hq_people`), структура группы
(`hq_projects`), настройки (`hq_settings`). Это и есть его память —
пополняется командами и переживает любую смену модели или чата.
